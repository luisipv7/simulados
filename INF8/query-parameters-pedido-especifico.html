🍹 O Pedido Específico

Query Parameters — Como pedir só o que você quer

👨‍🏫

PROFESSOR

Nas aulas passadas você aprendeu que o fetch() é o garçom e a API Python é a cozinha.

Hoje vamos aprender a fazer um pedido específico — não "me traga suco", mas "me traga suco de laranja com gelo". Esse detalhe extra se chama Query Parameter!

🍽️ A Regra do Restaurante

🧃
Pedido Geral
— Me traga um suco.

O garçom não sabe qual suco você quer. Pode trazer qualquer um!

http://site.com/suco
🍊
Pedido Específico (com Query Parameter)
— Me traga um suco de laranja!

Agora o garçom sabe exatamente o que você quer. O detalhe extra fica depois do ? na URL.

http://site.com/suco?tipo=laranja
📌 Esta aula tem 3 partes: (1) Entender a anatomia da URL, (2) Montar URLs com o construtor interativo, (3) Quiz de fixação.

Base URL (endereço do servidor)
/tasks (rota da API)
? (início dos parâmetros)
status (chave do filtro)
= (igual)
pendente (valor que você quer)

🗺️ O Mapa da URL

http://127.0.0.1:8000 🏠 Endereço do servidor. É o "endereço do restaurante".
/tasks 📋 A rota — diz QUE baú de dados você quer abrir.
❓
? O ponto de interrogação é o sinal que separa a rota dos filtros. Sempre vem um único ? antes do primeiro parâmetro.
status=pendente chave=valor — o filtro. Aqui: "me dê só as tarefas com status = pendente".
E se quiser 2 filtros?
Use & entre eles:
/tasks?status=pendente&owner=Luis

📋 Exemplos da Prática Guiada

1
Buscar tarefas "pendentes"
http://127.0.0.1:8000/tasks?status=pendente

O status é a chave do filtro. O valor pendente é o que você quer buscar.

2
Buscar tarefas do usuário "Luis"
http://127.0.0.1:8000/tasks?owner=Luis

Mudou só a chave (owner) e o valor (Luis). A rota e o servidor são os mesmos!

💻 No JavaScript, o fetch() monta essa URL automaticamente quando você usa um campo de busca. O usuário digita o valor — o código coloca na URL!
